## Project Overview

A dance school management application built as an ASP.NET Core + React SPA. The .NET backend serves both the API and the compiled React client as static files. Target framework: **net10.0**.

## Environment Variables (Required)

The server reads two environment variables at startup — without them the app will warn and fail at runtime:

| Variable | Purpose |
|---|---|
| `DanceSchoolApp_DB` | SQL Server connection string |
| `DanceSchoolApp_JWT_Secret` | JWT signing secret (minimum 32 characters) |

## Commands

### Backend (.NET)

Run from `DanceSchoolApp.Server/`:

```bash
# Build
dotnet build

# Run (starts API + SPA proxy)
dotnet run

# EF Core migrations
dotnet ef migrations add <MigrationName>
dotnet ef database update
```

### Frontend (React + Vite)

Run from `danceschoolapp.client/`:

```bash
npm install
npm run dev      # dev server on https://localhost:5173
npm run build    # production build
npm run lint     # ESLint
npm run preview  # preview production build
```

### Full Stack (Visual Studio)

Open `DanceSchoolApp.slnx`. Running the server project launches both the .NET backend and the Vite dev server via the SPA proxy. The backend proxies to `https://localhost:58720` during development.

## Architecture

### Backend (`DanceSchoolApp.Server/`)

**Service registration** — All classes whose names end in `Service` are auto-registered as scoped services via reflection in `Program.cs`. No manual `AddScoped<>` calls needed.

**Domain areas** — Controllers, Services, and DTOs are each split into sub-folders by domain:
- `Classes/` — Coach classes, participants
- `People/` — Users, coaches, students, parents, staff, roles
- `Inventory/` — Items, variants, categories, requisitions
- `Scheduling/` — Coach availability, blocked periods, modalities, studios
- `School/` — School-level settings, events
- `Social/` — News posts, notifications, communication
- `Auth` (root level) — Login, logout, `/api/auth/me`

**Auth flow** — JWT is issued on login and stored in an `HttpOnly Secure SameSite=Strict` cookie named `jwt`. The `JwtBearerEvents.OnMessageReceived` handler reads the token from the cookie instead of the `Authorization` header, so the frontend never touches the token directly. `GET /api/auth/me` lets React restore session state from JWT claims without a DB call.

**Database** — SQL Server via EF Core. `AppDbContext` is in `Data/AppDbContext.cs`. Roles are seeded: `admin (0)`, `staff (1)`, `coach (2)`, `parent (3)`.

**User → PersonInfo relationship** — `User` has an optional FK to `PersonInfo`, which holds name, birth date, address, phone. `Student` also links to `PersonInfo` and to a parent `User`.

### Frontend (`danceschoolapp.client/src/`)

React 19 + React Router 7 SPA. Current pages: `HomePage`, `LoginPage`. Components are in `components/` (landing page sections: `Hero`, `Navbar`, `Footer`, `Features`, `Modalities`, `Testimonials`, `About`). Path alias `@` maps to `src/`.

The Vite config proxies API routes to the .NET backend. Dev HTTPS uses a certificate generated by `dotnet dev-certs`.

## Key Conventions

- Controllers inherit `ControllerBase` with `[ApiController]` and route prefix `api/<domain>`.
- Services receive `AppDbContext` via constructor injection; they do not access `HttpContext` — that stays in the controller layer.
- Password hashing uses **BCrypt.Net-Next**.
- Column names in the DB use `snake_case`; C# properties use `PascalCase` — mapped explicitly in `OnModelCreating`.
- Controllers resolve the authenticated user's id from JWT claims using
  `User.FindFirstValue(ClaimTypes.NameIdentifier)` — never trust UserId
  from the request body. See `ItemController.GetUserId()` for the pattern.
- Ownership checks on parent-scoped endpoints: if the requesting user is
  not staff, verify the resource belongs to them before returning it.
